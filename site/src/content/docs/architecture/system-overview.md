# System Overview

## Overview

The Video Denoise system is a biologically-inspired audio enhancement pipeline designed to investigate whether Spiking Neural Networks (SNNs) can recover useful audio information from noisy video recordings.

The architecture combines traditional audio processing techniques with neuromorphic computation, using a Liquid State Machine (LSM) reservoir as the central processing component.

The complete system transforms an input video into a reconstructed video containing an enhanced audio track.

---

## System Objectives

The architecture has been designed to satisfy several key objectives:

- Extract audio from arbitrary video sources
- Convert continuous audio into spike-based representations
- Process temporal information using a recurrent spiking reservoir
- Learn useful signal representations through biologically-inspired mechanisms
- Reconstruct an enhanced audio waveform
- Recombine processed audio with the original video

The primary research goal is to determine whether this neuromorphic pipeline can improve objective audio quality metrics when compared with the original noisy recording.

## Processing Stages

### 1. Video Ingestion

The system accepts a standard video file as input.

Supported formats may include:

- MP4
- MOV
- AVI
- MKV

The video stream itself is not modified during neural processing.

Only the audio component enters the denoising pipeline.

---

### 2. Audio Extraction

The audio track is extracted from the source video and converted into a standardised format.

Initial configuration:

| Parameter | Value |
|------------|--------|
| Format | WAV |
| Sample Rate | 16 kHz |
| Channels | Mono |
| Bit Depth | 16-bit |

The resulting waveform becomes the input to the encoder.

---

### 3. Audio Encoding

The waveform is transformed into spike-based data.

The encoder performs:

```text
Waveform
     │
     ▼
Frequency Analysis
     │
     ▼
RMS Extraction
     │
     ▼
Population Coding
     │
     ▼
Spike Generation
```

The objective is to preserve useful temporal and spectral information while producing biologically-inspired event streams.

Initial design:

```text
16 Frequency Bands
×
4 Threshold Neurons

=
64 Input Neurons
```

The resulting spike trains form the sensory input to the Liquid State Machine.

---

### 4. Input Population

Input neurons receive the encoded spike trains and inject activity into the reservoir.

Neuron model:

```text
iaf_psc_alpha
```

Responsibilities:

- Receive external spikes
- Transform encoded features into neural activity
- Stimulate the recurrent network

These neurons act as the interface between conventional signal processing and spiking computation.

---

### 5. Liquid State Machine Reservoir

The reservoir is the central computational component.

Its purpose is not to directly reconstruct audio, but rather to generate rich temporal representations of incoming signals.

Initial configuration:

```text
500 Neurons
```

Population split:

```text
400 Excitatory
100 Inhibitory
```

Key biological mechanisms include:

- Sparse connectivity
- Recurrent processing
- Lateral inhibition
- Variable synaptic delays
- Synaptic plasticity

The dynamic state generated by the reservoir is referred to as the *liquid state*.

---

### 6. Learning

Learning occurs through two complementary mechanisms.

#### STDP

Spike-Timing-Dependent Plasticity allows reservoir synapses to adapt according to spike timing relationships.

Purpose:

- Improve internal representations
- Strengthen useful pathways
- Reduce less informative connections

#### ReSuMe

The Remote Supervised Method is used within the readout layer.

Purpose:

- Learn desired output spike patterns
- Support waveform reconstruction
- Improve denoising performance

Together these mechanisms provide both unsupervised and supervised learning capabilities.

---

### 7. Readout Layer

The readout layer observes the state of the reservoir and converts neural activity into a representation suitable for reconstruction.

Inputs:

```text
Reservoir Activity
```

Outputs:

```text
Reconstructed Signal Representation
```

The readout layer is responsible for translating complex neural dynamics into information that can be converted back into audio.

---

### 8. Audio Reconstruction

The output representation is transformed into an audio waveform.

Conceptually:

```text
Spike-Derived Output
          │
          ▼
Signal Reconstruction
          │
          ▼
Enhanced Waveform
```

The reconstructed signal is then evaluated against available reference data.

---

### 9. Video Remuxing

Once reconstruction is complete:

```text
Original Video
```

and

```text
Enhanced Audio
```

are combined into a new output file.

The resulting video maintains the original visual content while incorporating the processed audio track.

## Evaluation Pipeline

Performance will be assessed using both signal-processing and spike-based metrics.

### Audio Metrics

- Signal-to-Noise Ratio (SNR)
- Segmental SNR
- Root Mean Square Error (RMSE)
- Correlation

### Spike Metrics

- Victor-Purpura Distance
- van Rossum Distance

### Computational Metrics

- Runtime
- Memory Consumption
- Simulation Stability

## Working Hypothesis

The central architectural hypothesis is:

> A biologically-inspired pipeline combining RMS encoding, a recurrent Liquid State Machine reservoir, adaptive synaptic learning, and supervised readout training can generate useful neural representations of noisy audio and support measurable improvements in reconstructed audio quality.

The remainder of the project implements, evaluates, and tests this hypothesis through controlled experimentation.
